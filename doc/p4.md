# Fröling S 3200 heating control (p4mqttd)

homectld shows and controls the Fröling S 3200 boiler control (pellet boilers P4, S4, T4, PE1, ...). The communication
with the control is done by the service `p4mqttd` ([p4mqttd/README.md](../p4mqttd/README.md), serial line, no database,
no WEB interface), everything else - display, history, charts, alerts, mails, rights - is done by homectld.
The stand alone [p4d](https://github.com/horchi/linux-p4d) is not needed any more.

**USE AT YOUR OWN RISK.** The service can write parameters and time programs of the heating control.
Read the disclaimer in [p4mqttd/README.md](../p4mqttd/README.md).

## Setup

1. Build and install `p4mqttd` on the machine the heating control is connected to (FTDI USB-serial converter at COM1 of the
   mainboard) - see [p4mqttd/README.md](../p4mqttd/README.md). Start it **read only** (`-r`) at first.
2. In the WEBIF *Setup -> Konfiguration -> Heizung S 3200* switch on *Anbindung über p4mqttd* (`p4Enabled`), the MQTT
   topic is `p4` by default (option `-T` of the service).
3. In *Setup -> Sensor Setup* the sensors `P4VA` (values), `P4DO` / `P4DI` (outputs / inputs), `P4AO` (analog outputs) and
   `P4UD` (state, mode and time of the control) show up (inactive). Activate the ones you need, only these are polled.
4. A new widget of such a sensor gets sensible defaults from the service (kind of widget, scale, pump / fan symbols,
   the animated images of the state of the heating, the pellet tank).

## The page 'S3200' (main menu)

The name of the page can be changed (*Name der Seite im Hauptmenü*), it is only shown if the service is switched on.
The tabs:

| Tab | Content | Right |
|-----|---------|-------|
| Service-Menü | the service menu of the control with the current values; parameters and time ranges can be changed (they are written to the heating at once!); buttons to read menu, sensors and time programs again | view; change: settings |
| Fehler | the error list (came, gone, acknowledged), button to read it from the control | view |
| Pellets | the pellet deliveries with days, stoker hours and consumption per stoker hour | control; change: full control |
| Schema | an own plant picture of the heating (*Bild des Schemas*) with the sensors placed on it, editable like the schema of the main menu (*Setup Schema* in the burger menu) | view; edit: settings |

## Further functions

- **Duration of the states**: the sensors `P4SD:<state>` ("... (Laufzeit/Tag)") show the minutes per state of the heating
  of today. The state sensor `P4UD:0x01` has to be recorded for it.
- **Mails**: on a fault and on a change of the state (*Status- und Fehler-Mails*, `p4Mail`, off by default). Receivers,
  script and *Mail Benachrichtigung* are the ones of the group *Mail*. Switch it on only if the p4d does not send the
  mails any more.
- **Time synchronization** of the clock of the control (*Zeitsynchronisation*): not before 3:00, at most once a day, only if
  the drift is larger than the given seconds, never in the read only mode of the service.
- **Pictures**: `htdocs/img/p4/` has the pictures of the heating types (`type/`, choose the type in the configuration) and the
  plant pictures for the tab *Schema* (`schema/`).

## Taking over the data of the p4d

`p4mqttd/scripts/p4d-migrate.sh` takes over the history (samples, min / max, errors, pellet deliveries, the alerts of the sensors and the elements of the
schema) of the database of the p4d into the one of homectld. It only reads the old database, does not overwrite anything and
writes only with `--run` (without it it is a dry run). Take a backup of the database of homectld first, see the head of the
script. The p4d and the service `p4mqttd -P` can run side by side (the serial line is protected by a semaphore), so you can
compare the values before the p4d is switched off.
